## 二、A 级冲突详情

### C01 — 10 类菜品清单完全不同（7.1.1 检测范围说明、附录 B）

| | 清单 |
|---|---|
| PRD 原文 | 米饭、面条、馒头、红烧肉、宫保鸡丁、清蒸鱼、炒青菜、番茄炒蛋、紫菜蛋花汤、苹果 |
| 实际实现 | 米饭(0)、馒头(22)、饺子(70)、红烧肉(83)、青椒肉丝(37)、西红柿炒鸡蛋(40)、清蒸鲈鱼(66)、麻婆豆腐(82)、蚝油西兰花(136)、冬瓜汤(74) |

**为什么冲突**：PRD 清单里的面条、宫保鸡丁、炒青菜、紫菜蛋花汤、苹果**都不在模型里**，而实际有的饺子、青椒肉丝、麻婆豆腐、蚝油西兰花、冬瓜汤**不在 PRD 里**。队友若按 PRD 建测试集，测出来的菜一半模型没见过。

**已改为**：按实际清单改写，并标注每道菜对应的 `food_id`；同时在附录 B 术语表同步更新清单。

> 待你决策：是接受这个新清单，还是反过来改数据去对齐 PRD 原清单（后者需重新准备这 5 类的训练图，成本高）。

### C02 — Top-3 由谁产出（表 7-1 能力分工、MI-01）

- **PRD**：表 7-1 只有「菜品检测（YOLOv8）→ 候选菜品列表 + 检测框」，MI-01 的 Top-3 看起来由检测模型产出。
- **实际**：检测模型**没有 Top-3 概念**（每个框只输出 1 个类别），且真实照片上主框类别正确率只有 **79.6%**；Top-3 = **99.6%** 是由 **分类模型 YOLOv8n-cls** 产出的。若按 PRD 用检测模型凑 Top-3，MI-01 直接不达标。

**已改为**：表 7-1 新增一行「菜品分类（Top-3 候选）｜YOLOv8-cls｜标准图｜前 3 个候选 + 概率；MI-01 的 Top-3 口径以此为准」；MI-01 测量方法中明确「前 3 个候选由分类模型输出」。

### C03 — 整餐估算与份量的承担方（表 7-1、3.1.2、4.5）

- **PRD**：「多模态大模型结合原图、候选菜品与检测框，输出整餐营养总量与子项清单（含估算份量）」——份量由大模型估。
- **实际**：**未接入任何大模型**。份量走三态来源（称重 / 份量参考 / 模型估算），整餐合计由规则层 `calc_meal` 确定性累加（`nutrition/calculator.py`）。

**已改为**：
- 表 7-1「整餐估算与子项拆分」承担方改为「规则层 + 食物营养库（本期）；大模型接入后改为『大模型出份量、规则层核算』」，输入改为「food_id + 三态重量」
- 3.1.2、4.5 相应段落改为规则层 + 三态重量描述
- 7.2 表 7-2「大语言模型」行标注「本期未接入，相关环节按规则层降级执行」

> 连带影响：MI-02（热量偏差 ≤15%）**目前无法验收**——真值需要称重，而份量是参考值。已在里程碑 4 退出标准中标注为待验收项。

### C04 — 营养数据来源（7.2 表 7-2、9.2、7.4 Food.source）

- **PRD**：「USDA FoodData Central 等」，`Food.source` 枚举只有 `usda / self`
- **实际**：营养库来自 **DFoodTJ-Nutr（density.xlsx，351 道中餐，Aqua-Calc / Mint Health 口径）**，按每 100g 清洗；USDA FDC 只做了资料盘点**未采用**（西餐为主、英文条目，与中餐成品菜映射成本高）

**已改为**：表 7-2 营养数据行改为 DFoodTJ-Nutr；9.2 依赖段改写并说明 USDA 未采用的原因；`Food.source` 枚举改为 `dfoodtj / usda / self`；附录 C 补 DFood-TJ 数据集出处；Q2 关闭。

> 注意：任务书里提到 USDA，如果老师要求必须体现 USDA，则需要做双库并存的映射层——这是个待决策项，不是我单方改 PRD 能解决的。

### C05 — MI-01 的测试集条件（1.4.3 表 1-2）

- **PRD**：「测试集 ≥200 张（每类 ≥20 张），**覆盖单一与混合餐、3 种光照与角度**」
- **实际**：500 张（每类 50 张）取自 **DFoodTJ-Rec 官方 test split 的真实照片，全部是单菜品**，光照与角度不受控。也就是说 99.6% 这个达标值**是在单菜品条件下取得的**，PRD 要求的混合餐场景**没有测过**。

**已改为**：如实写明测试集来源与「单菜品场景」，并把「混合餐与光照/角度变化场景本期未覆盖」列为补充测试项。

> 这是我认为最需要你知晓的一点：达标是真实的，但条件比 PRD 窄。

- **2.x 权限与数据隔离**、**5.x 后台模块**、**1.4.4 优先级裁剪顺序**、**1.6 非目标** —— 与本工作包无关，无冲突

## 五、PRD 改不了、需要你决策的事项

这 5 项不是改文档能解决的，必须由人或数据来定：

1. **真实多菜品标注数据**：检测模型在合成数据上训练，真实多菜品照片的验收基准缺失。需人工标注 ≥200 张，否则 MI-01 的「混合餐」场景无法真正验收。
2. **份量基准校准**：`reference_portions.csv` 目前是 10 类经验值（`reference_only`）。不校准，MI-02（偏差 ≤15%）无法验收。
3. **是否接入多模态大模型**：接入后表 7-1 / 3.1.2 / 4.5 需再改回（份量由大模型估），且 MI-03 要按含 API 调用的口径重测。
4. **营养源是否要体现 USDA**：任务书提到 USDA，若必须体现，需做 DFoodTJ ↔ USDA 映射层。
5. **10 类清单**：接受实际清单（改 PRD，已做），还是改数据去对齐 PRD 原清单（成本高）。
