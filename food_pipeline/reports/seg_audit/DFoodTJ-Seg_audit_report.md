## 0. 一句话结论

mask 是**实例掩码**（像素值 = 图内实例序号 1..N），标注质量高、bbox 可精确提取；**但类别标签在导出时已丢失**（导出脚本从未读取 `shape['label']`），zip 内也没有任何映射表——因此**不能直接转成带类别的 YOLOv8 检测/分割数据**，但可以**立即转成"单类 food"的真实多菜品检测评测集**，这恰好补上本项目最大的验收缺口。

## 3. 掩码类型判定（问题 4）

**判定：实例掩码（instance mask），既非二值掩码、也非类别掩码。**

判断依据（全部来自实际像素，非文件名推断）：

1. **值域 = {0,1,…,N} 且逐图不同**：40/40 张采样满足"唯一值连续从 1 到 max"。类别掩码的值应是固定类别 ID 集合（DFoodTJ 论文称 187 类），不会每图恰好连续、且 max 逐图变化（1/2/4/10/28…）。
2. **max 值与图中食物份数吻合**：可视化核验中，max=10 的 `001771.png` 恰好是 10 个鸡蛋（每个实例一个蛋）；max=4 的 `000041.png` 恰好是 4 道菜（汤、皮蛋、青菜、午餐肉）。
3. **同一道菜的不同个体是不同值**：`001771` 里 10 个鸡蛋值 1–10 各不相同 → 值语义是"实例序号"而非"类别"。
4. **单通道 uint8** 与导出脚本中 `mask=np.zeros(...,dtype='uint8')`、`mask[rr,cc]=i; i=i+1` 的逻辑完全对应。

## 4. `generating_program/groundtruth_export.py` 分析（问题 5）

脚本原文已完整读取（1397 字节），逻辑如下：

```
输入：./data/*.jpg（原图） + ./json/*.json（labelme 格式标注，含 shapes[].points / shapes[].label）
处理：逐 shape 用 skimage.draw.polygon 把多边形内部填充为 i（i 从 1 递增）
      若 H>W 则转置+上下翻转（EXIF 方向校正）
输出：maskrcnn_groundtruth/000001.png（uint8 实例掩码）
      img/000001.png（导出原图，count 按 json 文件名排序递增）
```

**关键事实：**

1. **用途**：把 labelme JSON 多边形标注批量导出为 Mask R-CNN 用的实例掩码图。
2. **输入输出**：如上；输出文件名是 `str(count).zfill(6)` 顺序号。
3. **类别映射来源**：**没有**。脚本只读取 `shape['points']`（多边形坐标），**从头到尾没有出现 `shape['label']`**——食物类别在导出那一刻就没有写入任何输出文件。
4. **能否恢复训练所需标注**：
   - ✅ 能恢复：每个实例的**像素级轮廓**与**轴对齐 bbox**（本项目已实际提取 6,887 个 bbox，见 `instance_boxes.csv`）；
   - ❌ 不能恢复：**类别标签**。json 原文件名与 6 位序号的对应关系也未保存（无 CSV/log），连"这张 Seg 图对应哪张原图"都无法从 zip 内部证据还原。
   - ⚠️ 附带发现：`uint8` 掩码理论上 >255 实例会溢出；实测最多 28 实例，**本次数据无溢出**。

## 5. 像素值 ↔ 食物类别映射（问题 6）

**结论：该映射不存在，且凭现有文件无法确定。**

- 像素值 `v` 的唯一语义 = "该图中第 v 个被标注的多边形实例"，同一张图内不同食物/不同个体取不同值，**跨图无任何一致性**（图 A 的 `1` 是米饭，图 B 的 `1` 可能是鸡蛋）。
- zip 内没有 `json/` 原始标注、没有类别表、没有文件名映射表——脚本输出即全部信息。
- 论文口径（DFoodTJ-Seg = 3,932 张 / 187 类）与实测 3,932 张吻合，但 187 类信息不在本 zip 内。

**可能的类别恢复路径（均需人工决策，本次未实施）：**

| 路径 | 做法 | 成本/风险 |
|---|---|---|
| A. 找回原始 json | 向数据作者/Science Databank 条目索要 `json/` 与 `data/` | 最干净，取决于外部可得性 |
| B. 与 DFoodTJ-Rec 图像匹配传标签 | 对 3,932 张 img 算感知哈希/pHash，与 Rec 的 284,933 张匹配，命中即继承其 food_id | 需解压 Rec 全量（约 20GB）；命中率先验未知；论文称 Seg 187 类 ⊂ Rec 351 类，理论上应可匹配 |
| C. 分类模型弱标注 | 用现有 cls10（仅覆盖 10 类试点）对**单实例图**打 Top-1 标签 | 只覆盖 10 类、且是模型预测非真值，只能当弱标注 |

## 7. 能否转 YOLOv8？（问题 8）

| 目标格式 | 可行性 | 依赖 |
|---|---|---|
| **单类检测**（YOLO det，class=0 "food"） | ✅ **立即可行** | 无——bbox 已实测可从掩码逐实例提取 |
| **多类检测**（真实菜名类别） | ❌ 现有文件不可行 | 需走 §5 路径 A/B/C 恢复类别 |
| **实例分割**（YOLO-seg，无类别） | ✅ 可行（掩码即轮廓真值） | 需把连通域转多边形 |
| **多类分割** | ❌ 同多类检测 | 同上 |

单类检测转换规则（已验证可行）：

```
对每张 000001–003932：
  img  : DFoodTJ-Seg/img/000NNN.png            → images/
  label: 对掩码每个 v∈{1..N}：
         bbox = (xs.min(), ys.min(), xs.max()+1, ys.max()+1)   # 已在 instance_boxes.csv
         YOLO 行 = "0 cx/W cy/H w/H"                           # class 恒为 0
注意事项：14 张 RGBA 原图需转 RGB；掩码为逐实例独立连通域，无重叠冲突。
```

## 8. 对本项目是否有利（重点评估）

**有利，且正面命中本项目当前最大的验收缺口。**

1. **补上"真实多菜品检测基准"**：此前工作包 B 的已知问题第 1 条是"检测模型无真实域验收基准，需人工标注 ≥200 张"。本数据集提供 **1,023 张真实多菜品图 + 高质量实例掩码**，掩码提取的 bbox **不依赖类别即可当定位真值**——可以立即评测现有 det10 模型在真实域的定位能力（检出率/IoU），把"合成域 mAP 0.89"之外补一块真实域证据。
2. **目标尺寸大**（bbox 中位占图幅 15.7%，小目标仅 0.3%），与饮食拍摄场景一致，适合做检测评测。
3. **74% 单实例图带像素级轮廓**：是未来"基于分割的份量估计"（PRD 体积估重路径，营养库已含 `density_g_ml`）的数据基础。
4. **诚实提醒**：多实例 ≠ 多菜品——`001771` 的 10 实例是 10 个鸡蛋（同菜多份）；评测定位时无影响，但若未来做类别级统计需甄别。

**不能直接带来的**：带菜名的多类检测/分割训练数据（类别缺失，见 §5）。
